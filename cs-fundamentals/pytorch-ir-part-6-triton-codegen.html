PART 6 / LOWERING TO THE GPU

From a loop to thousands of lanes.

A generated Triton kernel mixes scalar launch metadata with vectors of block elements. Learn to read the launch grid, recover the original loop, check every pointer, and see exactly where fusion erased memory traffic.

The key shift: a Triton “program” is not one scalar thread. It is one independently launched program instance operating on a block of values.
output_code.py
pid = tl.program_id(0) offs = pid * XBLOCK + tl.arange(0, XBLOCK) mask = offs < xnumel x = tl.load(in_ptr0 + offs, mask) y = tl.sin(tl.cos(x)) tl.store(out_ptr0 + offs, y, mask)
LOOP i→PROGRAM pid→BLOCK [i…i+B)→GPU

02

The missing middle: loop IR

Inductor’s define-by-run loop IR represents a tensor result as an iteration domain plus a callable body. The body says what one logical element does; codegen supplies many logical indices at once.

Scalar mental model

for i in range(N): a = load(x, i) b = cos(a) c = sin(b) store(out, i, c)

One iteration at a time. Excellent for reasoning about semantics, terrible as the final GPU schedule.

→

Blocked Triton model

i = pid * B + arange(B) active = i < N # every value below is a vector a = load(x + i, active) b = cos(a) c = sin(b) store(out + i, c, active)

The scalar body is replayed with a block tensor of indices. The Triton compiler decides how those elements map to hardware threads and vector instructions.

Operation-for-operation mapping

ranges = [N]One flattened pointwise iteration domain.
ops.load("x", i)tl.load(in_ptr0 + x0, xmask)
ops.cos(v)tl.cos(tmp0), usually register-resident.
ops.sin(v)tl.sin(tmp1), still register-resident.
ops.store("out", i, v)tl.store(out_ptr0 + x0, tmp2, xmask)

04

Grid, program IDs, and the tail mask

The Python wrapper launches enough program instances to cover N. Each program receives a different ID and creates XBLOCK candidate indices. Only indices below N are active.

Launch laboratory

Change N and block size. The final program’s extra lanes become masked.

active: load + compute + storemasked: no memory access
grid = (ceil_div(37, 16),) = (3,)

Do not read it as CUDA thread IDs

tl.program_id(0) chooses a program instance. tl.arange builds a block tensor. Triton later maps that block to hardware threads. “One arange lane = one CUDA thread” is an unreliable mental model.

Why power-of-two blocks appear

Triton’s block shapes and compiler heuristics commonly use powers of two. Inductor’s size hints and autotuning select a configuration that balances occupancy, memory coalescing, and register pressure.

05

Index algebra is the map back to tensors

Generated kernels often flatten an iteration domain, then recover logical dimensions with division and remainder. Pointer formulas reveal layout, broadcasting, transpose, and reuse.

Flatten [rows, cols] → 1D

xindex = pid * XBLOCK + arange(...) row = xindex // COLS col = xindex % COLS addr = base + row*stride0 + col*stride1

For a contiguous tensor, stride0 = COLS and stride1 = 1, so the address simplifies to the flat index.

Broadcast [rows, 1] across columns

row = xindex // COLS bias_addr = bias_ptr + row x_addr = x_ptr + xindex y = load(x_addr) + load(bias_addr)

The repeated bias_addr across every column is the broadcast. No tensor expansion needs to be materialized.

Example [3 × 4]

flat index 6 → row 1, col 2

Stride-reading rule. The coefficient multiplying a logical coordinate is its stride in elements. Modulo isolates a coordinate; integer division advances to an outer dimension. A missing coordinate usually means broadcast reuse.
06

Fusion wins by deleting round trips

For chained pointwise operations, the arithmetic was never the expensive part. The key is keeping intermediates like tmp1 and tmp2 inside a kernel instead of materializing whole tensors in global memory.

Unfused: cos kernel + sin kernel

4N global-memory element transfers
read x
write tmp
read tmp
write y

Fused: one generated kernel

2N global-memory element transfers
read x
registers
write y

What proves fusion?

Both transcendental operations occur between one load and one store in the same kernel. There is no pointer or allocation for the intermediate.

Why fusion can stop

Incompatible iteration orders, mutation/aliasing constraints, reductions, device changes, unsupported ops, or register-pressure tradeoffs can force a boundary.

07

Reduction kernels add a second axis

A pointwise kernel has an output index. A reduction kernel also traverses a reduction index. In generated names, x* often tracks outputs and r* tracks the dimension being collapsed.

1 · X program

Choose one block of output positions with xindex.

2 · R tile

Create rindex = roffset + tl.arange(0, RBLOCK).

3 · Mask + load

Combine xmask and rmask; inactive reduction lanes use an identity.

4 · Combine

Apply tl.sum, tl.max, or helper reduction and store one result.

# conceptual shape; exact generated code varies xindex = xoffset + tl.arange(0, XBLOCK)[:, None] rindex = roffset + tl.arange(0, RBLOCK)[None, :] mask = (xindex < xnumel) & (rindex < rnumel) v = tl.load(in_ptr + xindex * R + rindex, mask, other=0.0) partial = tl.sum(v, axis=1) tl.store(out_ptr + xindex[:, 0], partial, xmask)
Advanced reading: look for whether the reduction fits in one program or requires multiple partials, atomic updates, or a second kernel. Then inspect RBLOCK, accumulator dtype, and whether the loads are contiguous along the reduction axis.
08

The wrapper is part of the performance story

output_code.py contains more than the kernel. The wrapper validates layouts, allocates outputs, computes launch dimensions, selects metadata, and invokes compiled kernels.

Launch math

grid = (triton.cdiv(xnumel, XBLOCK),) kernel[grid](in_ptr0, out_ptr0, xnumel, XBLOCK=chosen_block, num_warps=chosen_warps)

cdiv is ceiling division. The mask makes the rounded-up launch safe.

Compile-time vs runtime

XBLOCK: tl.constexprcompile-time specialization; usable in shapes
xnumelruntime scalar, unless the generated kernel specializes it
in_ptr0device pointer passed by the wrapper
num_warpslaunch/config metadata, not tensor data

Name decoder

triton_poi_…pointwise-style iteration
triton_red_…reduction-style kernel
fused_add_relu_0human hint about fused ops; verify the body, not just the name
in_out_ptr0buffer is mutated or reused in place
tmp0, tmp1…SSA-like temporaries; usually registers, not allocated tensors

Read your own generated output

Use a tiny, deterministic function first. Warm it once to trigger compilation, then inspect the emitted wrapper and kernel. Generated text changes across PyTorch/Triton releases, so trust structure over cosmetics.

A kernel has many % and // expressions. What now?

Write down the original tensor shapes beside the code. Rename x0/x1 to semantic coordinates. Factor each pointer expression into coordinates × strides. You are reverse-engineering a layout transform.

Why is xnumel an argument and then assigned a constant?

The calling convention may keep a general scalar argument while codegen specializes the body for a guarded shape. The overwrite makes the specialization explicit and can enable constant folding.

Why do I see an external GEMM call instead of Triton source?

Not every operation uses generic pointwise codegen. Inductor may select an external library kernel or a specialized template. Read the wrapper’s call sequence to see the boundary and any fused prologue/epilogue kernels around it.

Does fewer kernels always mean faster?

No. Fusion removes launches and memory traffic, but an oversized kernel can increase register use, lower occupancy, or create poor access patterns. Confirm with profiling and benchmark representative shapes.

10

A five-pass reading protocol

Use the same order every time. It separates semantics from scheduling and stops temporary names from becoming noise.

Find the output domainLocate xnumel/rnumel, block constants, and the grid expression.
Decode every indexTranslate modulo/division into named dimensions; annotate stride coefficients.
Trace store → loadsRecover the scalar formula from the final stored value back to source pointers.
Mark memory vs registersPointers and tl.load/store touch global memory; ordinary temporaries are usually register values.
Challenge the scheduleCheck coalescing, masked tails, fusion boundaries, block sizes, reduction shape, and register pressure—then profile.

Exercises: one concept at a time

  1. Compile x + 1. Predict load count, store count, and index formula before opening the output.
  2. Compile sin(cos(x)). Verify the intermediate has no allocated pointer.
  3. Compile x + bias[:, None]. Find the repeated broadcast address.
  4. Compile x.transpose(0,1) + 1. Explain the changed stride formula.
  5. Compile x.sum(dim=-1). Identify the output and reduction axes.
  6. Vary a non-multiple-of-block input size. Explain why correctness survives the tail.
