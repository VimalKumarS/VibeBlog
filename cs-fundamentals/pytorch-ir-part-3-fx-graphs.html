01 / Mental model

FX is executable Python IR

Not a picture of your model. Not a GPU kernel. A mutable, ordered graph that can regenerate runnable Python.

An IR sits between the program you wrote and the program a compiler wants to analyze. FX records what produces each value, not every incidental line of Python used to express it.

Eager execution

Python chooses an operation, PyTorch runs it, then Python chooses the next one. The future is invisible, so whole-program rewrites are hard.

Graph execution

Capture first. The graph exposes dependencies, users, and operation targets. A pass can inspect or rewrite the program before execution.

same computation, two representationssource → IR
# Python source
y = self.proj(x)
y = torch.add(y, 0)
return torch.relu(y)

# FX's conceptual dataflow
x → call_module[proj] → call_function[add](·, 0) → call_function[relu] → output
Boundary to remember

FX is a graph IR at roughly Python/PyTorch operator granularity. Later compiler stages may decompose operations, make shapes symbolic, fuse loops, and generate Triton or C++. “An FX graph” does not imply one fixed operator dialect.

make + inspectPython
import torch
import torch.nn as nn
import torch.fx as fx

class Tiny(nn.Module):
    def __init__(self):
        super().__init__()
        self.proj = nn.Linear(4, 4)
        self.register_buffer("scale", torch.tensor(0.5))

    def forward(self, x, bias):
        y = self.proj(x)
        y = torch.relu(y)
        return y * self.scale + bias

model = Tiny().eval()
gm = fx.symbolic_trace(model)
print(gm.graph)       # structural IR
print(gm.code)        # generated forward
gm.graph.print_tabular()
GraphModule owns referenced state

If a node targets proj or scale, the GraphModule keeps those attributes. A call_module target resolves through gm.get_submodule(target); a get_attr target resolves through normal attribute lookup.

03 / Vocabulary

Every node answers four questions

op: what kind? target: what is invoked/read? args/kwargs: what flows in? users: who consumes it?

placeholder

Graph input

One node per forward parameter. Its target is normally the parameter name. No tensor exists during symbolic tracing; the node represents a future value.

%x : [num_users=1] = placeholder[target=x]
get_attr

Read module state

Fetches a parameter, buffer, or other attribute from the module hierarchy. The target is a qualified path such as scale.

%scale = get_attr[target=scale]
call_function

Call a free function

Targets a Python callable: torch.relu, operator.add, or another wrapped function. Arguments can contain nodes and literals.

%relu = call_function[target=torch.relu](args=(%proj,))
call_module

Call a child module

The target is a string path into the module tree. During execution, FX resolves the child and calls it.

%proj = call_module[target=proj](args=(%x,))
call_method

Call a value method

The target is a method-name string. The receiver is the first item in args, as in x.view(...) or x.relu().

%view = call_method[target=view](args=(%x, -1))
output

Graph return

The single sink node. Its first positional argument describes the returned structure: one node, tuple, list, or nested pytree.

return (%add,)
Why call_method appears here

The request’s five node kinds cover the worked model, but FX has six canonical operation kinds. Method syntax is semantically distinct from a free-function call, so a robust pass must decide whether it handles both spellings.

04 / Capture

Symbolic tracing executes with stand-ins

The tracer runs your Python once, but replaces tensor inputs with Proxy objects that record operations instead of computing tensor data.

1 · INPUTTracer creates a placeholder Node.
2 · PROXYA Proxy wraps that node.
3 · INTERCEPTOperations on Proxy are intercepted.
4 · RECORDTracer adds a new Node and edges.
5 · RETURNA GraphModule is generated.
what conceptually happenspseudo-code
x_proxy = Proxy(placeholder_node)

# Your source executes:
y = torch.relu(x_proxy)

# Proxy/tracer records instead of calculating:
relu_node = graph.call_function(torch.relu, args=(x_proxy.node,))
y = Proxy(relu_node)

Modules are usually leaf calls

By default, familiar torch.nn modules are treated as leaves: FX emits one call_module rather than tracing every Python line inside them. Your own modules are usually traced through. Override Tracer.is_leaf_module() when that boundary is wrong for your tool.

custom leaf policyPython
class MyTracer(fx.Tracer):
    def is_leaf_module(self, module, qualified_name):
        if isinstance(module, MyOpaqueBlock):
            return True
        return super().is_leaf_module(module, qualified_name)

tracer = MyTracer()
graph = tracer.trace(model)
gm = fx.GraphModule(tracer.root, graph)

Where symbolic tracing stops

Data-dependent Python control flow

if x.sum() > 0 asks for a real boolean from a Proxy. One static graph cannot choose a branch without specializing or a richer capture mechanism.

Static structure

Loops over a fixed module list, fixed integer ranges, and decisions from configuration can execute while tracing because Python can resolve them.

Escape hatch: specialize with concrete_args

fx.symbolic_trace(fn, concrete_args={"training_path": False}) traces one chosen path. Treat the result as specialized: it does not become a general dynamic-control-flow graph.

Escape hatch: keep a helper opaque with fx.wrap

Register a top-level helper with torch.fx.wrap so the tracer emits a call_function node instead of entering the helper. This changes the tracing boundary; the function still runs when the GraphModule executes.

Why torch.compile capture is different

torch.compile starts with TorchDynamo, which observes Python bytecode and can emit FX GraphModules plus guards and graph breaks. The graph container is familiar, but capture semantics and operator targets differ from a direct symbolic_trace.

05 / Reading

Read dataflow, not source order alone

Node order is topological, but the real program is encoded by references between nodes.

tabular mental modelrepresentative output
opcode         name    target                     args
-------------  ------  -------------------------  ---------------
placeholder    x       x                          ()
placeholder    bias    bias                       ()
call_module    proj    proj                       (x,)
call_function  relu    <built-in method relu>     (proj,)
get_attr       scale   scale                      ()
call_function  mul     <built-in function mul>    (relu, scale)
call_function  add     <built-in function add>    (mul, bias)
output         output  output                     (add,)

Scan placeholders and output

Establish the graph’s interface before reading the middle.

Resolve targets by operation kind

proj means a module path only because its op is call_module. The same string under call_method would mean a method name.

Follow Node references inside args

Literals do not create graph edges. Node objects do. Containers can nest both.

Use users for fan-out

node.users is a mapping of consuming nodes. It is essential for safe deletion and pattern matching.

Inspect meta, but do not assume it exists

Shape propagation and compiler capture may attach tensor metadata, source stacks, or module stacks under node.meta. Plain symbolic tracing does not guarantee these.

Names are for humans, targets define behavior

A node called relu_1 is only a unique identifier. Match node.op and node.target, not the generated name.

class WithIdentityAdd(nn.Module):
    def __init__(self):
        super().__init__()
        self.proj = nn.Linear(4, 4)

    def forward(self, x):
        y = self.proj(x)
        y = torch.add(y, 0)
        return torch.relu(y)
complete passPython
import operator
import torch.fx as fx

def remove_add_zero(gm: fx.GraphModule) -> fx.GraphModule:
    graph = gm.graph

    # Snapshot the list: mutation during iteration stays predictable.
    for node in list(graph.nodes):
        # 1) Match the operation spelling(s) this pass supports.
        if not (node.op == "call_function" and
                node.target in (torch.add, operator.add)):
            continue

        lhs, rhs = node.args[:2]
        replacement = None
        if rhs == 0 and isinstance(lhs, fx.Node):
            replacement = lhs
        elif lhs == 0 and isinstance(rhs, fx.Node):
            replacement = rhs
        if replacement is None:
            continue

        # Rewire consumers before deleting the old producer.
        node.replace_all_uses_with(replacement)
        graph.erase_node(node)

    graph.lint()
    gm.recompile()
    return gm

The graph surgery contract

OperationWhat it changesCommon mistake
graph.inserting_before(n)Controls where newly created nodes enter the topological list.Creating a node after one of its users.
graph.call_function(...)Creates a node; arguments can reference existing nodes.Calling the function directly and computing a value.
node.replace_all_uses_with(new)Rewrites every consumer edge from old to new.Replacing uses after erasing the producer.
graph.erase_node(node)Removes a node only when it has no users.Ignoring side effects or hidden mutation.
graph.eliminate_dead_code()Removes unused nodes FX considers pure.Assuming every Python callable is side-effect free.
graph.lint()Checks ownership, ordering, and target validity.Treating it as semantic equivalence testing.
gm.recompile()Regenerates executable forward from the graph.Editing graph, then executing stale code.
Correctness scope

x + 0 → x is a teaching rewrite, not a universal production theorem. Operator overloads, quantized/sparse/custom tensor types, side effects, aliasing, dtype promotion, and autograd behavior can invalidate “obvious” algebra. State and document the accepted input domain of every pass.

validation harnessPython
model = WithIdentityAdd().eval()
gm = fx.symbolic_trace(model)
x = torch.randn(8, 4)

with torch.no_grad():
    expected = gm(x)

remove_add_zero(gm)

with torch.no_grad():
    actual = gm(x)

torch.testing.assert_close(actual, expected)
assert not any(
    n.op == "call_function" and n.target in (torch.add, operator.add)
    for n in gm.graph.nodes
)
07 / Reliability

A pass is not done when it runs once

Structural validity, executable code, and semantic equivalence are three separate checks.

1 · Structure

graph.lint(): nodes belong to this graph, uses are topologically valid, referenced module targets exist.

2 · Execution

gm.recompile(), then run representative inputs in train/eval modes and on intended devices.

3 · Semantics

Compare outputs, gradients, dtypes, shapes, aliasing, mutation, exceptions, RNG behavior, and state updates as relevant.

4 · Coverage

Test non-matches, shared users, nested containers, kwargs, edge shapes, empty tensors, and operator spelling variants.

Failure map

“symbolically traced variables cannot be used as inputs to control flow”
The Python program tried to turn a Proxy into a concrete boolean or integer. Refactor to tensor operations, specialize a static argument, define a leaf boundary, or use a capture system designed for that control flow.
My pass misses an add that is clearly present
Inspect both op and the exact target. x + y may target operator.add; torch.add(x, y) may target torch.add; compiler-produced graphs may use an ATen overload such as torch.ops.aten.add.Tensor.
The printed graph changed, but execution did not
You probably forgot gm.recompile(). The graph is the editable representation; the generated forward must be rebuilt.
erase_node says the node still has users
Rewire consumers first. Check node.users, call replace_all_uses_with or update individual inputs, then erase.
A transformed model’s state_dict looks surprising
Graph surgery and module-tree surgery are related but separate. Adding, removing, sharing, or renaming child modules changes state ownership and serialized keys. Plan state migration explicitly.

Knowledge check

A pass replaces a node in gm.graph, calls graph.lint(), and immediately runs gm(x). Output is unchanged. What is the best first diagnosis?

08 / Lab

Build the muscle in four runs

Do these in a notebook. Do not skip printing the graph before and after.

Trace and annotate

Trace Linear → ReLU → Linear. For every node, write its op, target type, args, and users in your own words.

Force every node kind

Add a buffer (get_attr), a tensor method (call_method), and a free function (call_function). Predict the graph before tracing.

Write two passes

Implement add-zero elimination, then a counter that records how many call_module nodes target nn.Linear. Separate transformation from analysis.

Break it deliberately

Erase a live node, omit recompile, match by name, and add data-dependent if. Read each failure until you can explain which layer objected.

Exit criterion

You are ready for AOTAutograd when you can look at an unfamiliar FX graph and answer: what is state, what is data, which node spelling is used, where a rewrite can be inserted, and how you will prove it preserved behavior.
