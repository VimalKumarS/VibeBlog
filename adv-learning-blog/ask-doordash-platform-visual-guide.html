Specialists behind one conversational identity

Routing buys testability and independent evolution. Pinning earns back the latency and token cost on normal follow-ups.

The new failure mode: skill selection itself must be evaluated. A selector that misses a needed skill or loads irrelevant skills simply moves the quality problem.

10 / APPLY

Portable lessons for any agent platform

The system-design value is in the boundaries: where probabilistic reasoning ends, what gets shared, and how every change earns production trust.

Platformize repetition, not possibility

Wait for multiple real consumers. Standardize the pieces whose divergence would create reliability or operations pain.

Use one edge contract

Hide agent protocols, streaming, and multimodal transport behind a Gateway so clients do not couple to internal agent topology.

Route coarse, load fine

Choose a specialized domain first, then load only the skill needed for the turn. This bounds both reasoning scope and prompt cost.

Put policy in code

Let the model select operations, but validate identity, input, permission, and business constraints in deterministic tool implementations.

Separate state by lifetime

Session, memory, and artifacts are distinct contracts. Treating them all as chat history creates reliability and lifecycle problems.

Make change the first-class workload

Tracing, evaluation, fallback, and rollout controls are what let teams safely swap models and evolve shared infrastructure.

Why not use a single general-purpose agent?

Restaurant, Grocery, and Reservations require different tools, policies, and evaluation criteria. One agent would increase context, coupling, and test complexity while forcing unrelated domains onto the same release cycle.

Why pin follow-up turns?

A full orchestration pass costs latency and input tokens even when the topic has not changed. Pinning makes the common path direct, while an out-of-scope signal still allows a same-turn reroute.

Why isn't a careful prompt enough for tool safety?

Prompts influence model behavior but cannot guarantee enforcement. A deterministic MCP boundary validates every call and applies permissions and business rules even when models or prompts change.

What should be evaluated besides answer quality?

Routing, skill selection, tool choice, latency, cost, regressions in shared code, and behavior under staged rollout all matter. Platform changes require a view across quality, cost, and latency.
