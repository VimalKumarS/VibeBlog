Loop Engineering Framework

Beginner to advanced — build a loop framework from a 5-line bash loop to a production harness. The inner loop is plumbing; the outer loop is what you engineer.

A loop framework has two loops. The inner loop is plumbing your harness already gives you. The outer loop is what you engineer — and the framework is just that outer loop, written down as data:

The ladder — climb one rung at a time. Each level exists because the level below it hurt:

L0First loop — a bash loop that runs the agent until tests pass
L1LoopSpec as data — trigger, goal, verify, stop, memory in a YAML file
L2Inner runner — your own ReAct loop: model call, tool dispatch, observation
L3Verification ladder — cheap checks first, maker-checker, never self-grade
L4Memory & tokens — PROGRESS.md, fresh context, truncation, caching
L5Safety & budgets — caps, stall detection, escalation, human gate
L6Triggers & queue — cron, webhooks, work selection rules
L7Parallel loops — one worktree per loop, sub-agents with capped returns
L8Observability — $/solved task, pass rate, evals on a fixed task set
L9Production — skills, self-improvement, recovery & resume

Level 0 is five lines of bash — the Ralph loop. Level 1 writes the same loop down as data, so the runner can read it instead of you re-typing it:

loop.yaml — the LoopSpec (L1: the loop as data)
trigger: manual            # run ./loop.sh by hand
goal: one failing test passes, nothing else regresses
verify: pytest -q          # the check is the stop signal
stop: pass OR 5 iterations
memory: PROGRESS.md        # append-only, 3–5 lines per iteration
budget: 30 min wall-clock

The framework insight: the spec is data, the runner is an interpreter of the spec. Once the loop lives in a file, you can version it, review it, copy it — and hand it to any harness.

Level 2 — the inner loop, written by you. It is one while loop with four moves. Everything else in a framework is scaffolding around this:

messages = [system_prompt, goal, memory]
while turns < MAX_TURNS:
    resp = model(messages)                 # one LLM call
    if resp has no tool_call:
        return resp.text                   # agent is done
    result = tools[resp.tool].run(resp.args)
    messages.append(resp.tool_call, result)
raise Stall("max turns reached")

Three parts to own: the tool registry (name → schema → handler), the prompt builder (system + goal + memory + history), and the stop conditions (no tool call, max turns, error). Every turn re-sends system prompt + tool schemas + full history — that is why the fixed block is the token tax (HarnessTax).

Level 3 — verification is a ladder, cheapest first. Level 4 — memory is a file, not the full history:

1Lint / syntax — seconds, catches typos before anything runs
2Unit tests — the target test, then the touched module
3Integration tests — the whole suite
4E2E / browser — only if 1–3 pass; the expensive check
5Human review — a PR, never auto-merge on the agent’s say-so
F
Fresh context per iteration.
Each iteration is a new agent call — history never accumulates in one window. That is the Ralph rule and the biggest token saver.
P
PROGRESS.md is the whole memory.
3–5 lines per iteration: what changed, what the test said, what still fails. No full logs, no pasted tool output.
T
Truncate observations.
Cap tool output at ~120 lines in context; full logs go to files. AgentDiet cuts trajectory tokens 40–60% the same way.
C
Cache the stable prefix.
System prompt + schemas billed as cache reads at ~0.1×. Keep PROMPT.md short and byte-stable — and load tool definitions lazily (77K → 8.7K tokens).

Golden rule: never let the maker grade itself. The checker must be a different agent (or deterministic code), and the check must be something the agent cannot talk its way past.

Level 5 — a loop without a budget is a billing incident. Level 6 — the loop needs a way to find its next job:

5
Max iterations.
Hard cap (5 is a good default). Hit it → STOP, read PROGRESS.md, fix the spec, rerun. Never loop unbounded.
$
Token & dollar budget.
Track tokens and cost per iteration; abort when the budget is spent. Log it — you cannot tune what you do not measure.
T
Wall-clock budget.
30 minutes for a first loop. A stuck loop that runs overnight is worse than a loop that stops and asks.
!
Stall detection.
Same tool output twice · no file delta after an iteration · failing-test count not decreasing → stop and escalate, don’t retry blindly.

Escalation ladder: retry (≤ 2) → try a different approach → human gate → abort. Every terminal state gets a name — COMPLETE, STALLED, BUDGET_EXHAUSTED, ESCALATED, FAILED — so the loop can report what happened instead of vanishing.

Triggers (L6): manual · cron schedule · file watcher · CI webhook (a failing test opens a loop) · work queue. Work selection: pick the next item by priority; skip it if the goal is ambiguous, it touches secrets/payments, or it failed twice before.

Safety boundary: run in a git worktree or a scratch copy, never your main checkout. Autonomous loops need permissions bypassed to run unattended — a sandbox is the only boundary left, so stay in the room for the first runs.

Level 7 — scale out with worktrees, one loop per worktree. Level 8 — measure the loop like a service. Level 9 — the loop starts improving itself:

$
Measure $/solved task.
Not pass rate alone, not cost alone — cost per solved task. HarnessTax’s whole point: the same model costs up to 5× across harnesses at the same success rate.
▦
Track four numbers.
Pass rate · turns per task · tokens per iteration · stall rate. If one moves, you know which level to fix.
S
Skills = codified knowledge.
SKILL.md files: how to build, test, and deploy this repo. The agent loads them on demand instead of re-learning them every run.
↻
Self-improvement (L9).
Hermes-style learning loop: experience → new skill → reuse. And recovery: crash-safe state in files, so a killed loop resumes instead of restarting.

Anti-patterns: agent edits the tests to pass (reward hacking) · model grades its own work · verification the agent can talk past · unbounded loops · context that grows forever. Every one of these has bitten a real loop — the LoopSpec paper catalogs them.

Yes — loop engineering is open source, and the best way to learn it is to read the loops, not just the essays. Start with Pi; it is the smallest real loop in the wild:

π
Pi — badlogic/pi-mono
Read this first. A minimal harness: 4 tools, a system prompt under 1,000 tokens. The whole loop fits in your head — and it was the cheapest harness in HarnessTax.
◉
OpenClaw — openclaw/openclaw
Gateway personal assistant, MIT, ~390k stars. Pi is its coding core. Study how the gateway routes sessions, tools, and channels.
H
Hermes Agent — NousResearch/hermes-agent
The learning loop: turns experience into skills, full-text search over past sessions. MIT, ~250k stars. Read it for L9 (self-improvement).
G
LangGraph — langchain-ai/langgraph
Graph-based orchestration: explicit state machines, human-in-the-loop interrupts. Reach for it when your loop needs branches, not just a cycle.
L
Loop Library / Loopy — Forward-Future/loopy
50 real loops with checks and stop rules, MIT, plus an installable skill. Copy a loop that fits; don’t invent one from scratch.
R
Ralph — ghuntley/how-to-ralph-wiggum
The canonical 5-line bash loop. This is Level 0, and it is still the pattern every other loop is measured against.
+
Also worth reading: Codex · OpenHands · OpenCode
Full coding harnesses at scale — read them after Pi, when you want to see how the same loop looks with sandboxing, permissions, and multi-model support.

How to use this list: read Pi’s loop in one evening → run one loop from the Loop Library → read LangGraph when you need branches. That is the fastest path from reading about loops to owning one.
