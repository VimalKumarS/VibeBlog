Chapter 01 · Beginner

The single idea you should leave with: 1.6% AI, 98.4% infrastructure.

If you remember nothing else, remember this ratio.

Open the Claude Code source and you'll find roughly 1,884 TypeScript files and ~512,000 lines of code. Of that, only a sliver — the queryLoop at the heart — is the part where "the AI decides what to do." Everything else is plumbing: permission rules, context shapers, tool routers, hook dispatchers, session writers, recovery handlers, sandbox wrappers, classifier callers.

Fig. 1 · Interactive
Where does the engineering live?

This single ratio reframes how to think about agent engineering. The model is the brain; the harness is the body. A more capable model arrives every quarter; the harness — the deterministic infrastructure that constrains and amplifies that model — is what you, as a builder, actually own.

Why this matters The Claude Code paper argues that as frontier models converge in raw capability, the harness becomes the differentiator. Two products on the same model can feel radically different depending on how their context is shaped, how their permissions gate, and how their tools are routed. The architecture is the product.

The architecture is not a hairball. Every decision traces back to a value.

The paper's deepest claim is structural: every design choice in Claude Code traces from a human value, through a design principle, down to a specific implementation in source. This is what makes the system internally coherent rather than a pile of features. Let's walk the chain.

The five human values

Value 01

Human Decision Authority

Humans retain control via the principal hierarchy. When a 93% prompt-approval rate revealed approval fatigue, the response was to restructure boundaries, not add more warnings.

Value 02

Safety, Security, Privacy

The system protects even when human vigilance lapses. Seven independent safety layers, each capable of blocking a request on its own.

Value 03

Reliable Execution

Does what was meant. A gather-act-verify loop with graceful recovery from errors, retries, and reactive compaction.

Value 04

Capability Amplification

"A Unix utility, not a product." The 98.4% deterministic infrastructure exists to make the model more useful, not to constrain it for its own sake.

Value 05 · spans bottom row

Contextual Adaptability

CLAUDE.md hierarchy, graduated extensibility, trust trajectories that evolve over time. The system meets users where they are and grows with them.

A 6th lens The paper adds an evaluative lens beyond the official five: long-term capability preservation. It cites evidence that developers in AI-assisted conditions score 17% lower on comprehension tests — a serious open question for any agent designer who cares about user growth.
Chapter 04 · Intermediate

The agentic query loop, step by step.

A while-loop, but with nine steps and five recovery paths.

At the heart of Claude Code is a ReAct-pattern async generator that yields streaming events. Each turn runs through a 9-step pipeline. Five compaction shapers run before every model call. Two execution paths handle tools — a streaming path that begins executing as tools arrive, and a fallback that classifies tools as concurrent-safe or exclusive.

Fig. 4 · Animated pipeline
A single turn through the queryLoop
9 steps · 5 shapers · 5 stop conditions · streaming + fallback paths

The 9-step pipeline

// Pseudocode of one queryLoop iteration
async function* queryLoop(state) {
  while (!stopCondition(state)) {
    1. settings    = resolveSettings(state)        // merge user/project/managed CLAUDE.md
    2. state      = initTurnState(state)
    3. ctx        = assembleContext(state)        // 9 ordered sources
    4. ctx        = runShapers(ctx)               // 5 compaction stages
    5. stream     = callModel(ctx)
    6. toolCalls  = dispatchTools(stream)
    7. approved   = permissionGate(toolCalls)     // deny-first, hooks, classifier
    8. results    = executeTools(approved)        // streaming or fallback
    9. state      = appendResults(state, results)
    yield events
  }
}
5 stop conditions The loop terminates when (1) the model returns no tool calls, (2) max turns reached, (3) context overflow, (4) a Stop hook intervenes, or (5) the user explicitly aborts. Notice that "task complete" is not a separate condition — it's just "no tool calls." The model itself signals completion by ceasing to act.
Chapter 05 · Intermediate

Five shapers battle the context window.

Cheapest first, last resort last. Graduated lazy degradation.

The 200K-token context window is the binding constraint of the entire system. Before every model call, the harness runs five compaction stages in order — each progressively more aggressive and more expensive. The principle is graduated lazy degradation: do the cheapest thing that works, escalate only when necessary.

Design choice worth stealing Stage 4 (Context Collapse) is non-destructive — it's a read-time projection, not a rewrite. The full transcript stays on disk; the model just sees a compressed view. This is what makes session resume coherent and what enables chain-patching at compact boundaries.
Chapter 06 · Intermediate

Deny-first, with seven layers.

A request must pass all of them. Any single layer can block it.

Claude Code's safety model is defense in depth. A tool request must pass through seven independent layers. Each one is capable of blocking the request on its own. The default posture is deny-first: a broad deny rule always overrides a narrow allow rule, no matter how specific the allow.

Fig. 6 · Try a request
Send tool requests through the 7-layer gauntlet
Click a tool · watch it pass or fail at each layer

The seven layers

  • 1. Tool pre-filtering — blanket-denied tools are removed from the model's view entirely. The model can't request what it can't see.
  • 2. Deny-first rule evaluation — explicit deny rules always override allows.
  • 3. Permission mode constraints — the active mode determines baseline handling (plan, default, auto, etc.).
  • 4. Auto-mode ML classifier — a separate LLM call evaluates safety independently. Two-stage: fast-filter + chain-of-thought.
  • 5. Shell sandboxing — filesystem and network isolation for shell commands.
  • 6. Non-restoration on resume — permissions never persist across session boundaries. Trust is re-earned each session.
  • 7. Hook-based interception — PreToolUse hooks can modify or block actions at runtime.

The seven permission modes — a graduated trust spectrum

Shared failure mode Defense in depth degrades when layers share constraints. The paper notes that per-subcommand parsing causes event-loop starvation — commands with more than 50 subcommands bypass security analysis entirely to keep the REPL from freezing. And four patched CVEs share a root cause: hooks and MCP servers execute before the trust dialog appears, creating a structurally privileged pre-trust window.

Three injection points in the agent loop

Point 1

assemble()

What the model sees. CLAUDE.md, skill descriptions, MCP resource snippets, hook-injected context.

Point 2

model()

What the model can reach. Built-in tools, MCP tools, the SkillTool meta-tool, the AgentTool for spawning subagents.

Point 3

execute()

Whether and how an action runs. Permission rules, PreToolUse / PostToolUse hooks, Stop hooks.

The 27 hook events, 4 execution types

Hooks are the cheapest extension point — zero context cost — and the most powerful gate. They fire at 27 distinct lifecycle events, organized into 5 categories. Each hook can run as a shell command, an LLM evaluation, a webhook call, or a subagent verifier.

Chapter 08 · Intermediate

Memory is just files.

No vector DB. No embeddings. The user can read it.

Claude Code's memory model is striking for what it doesn't do. There is no vector database, no embedding store, no opaque retrieval layer. Memory is plain Markdown files — fully inspectable, editable, and version-controllable. Retrieval is an LLM-based scan of file headers, picking up to five relevant files on demand.

Fig. 8 · Hierarchy
The 4-level CLAUDE.md hierarchy
Managed → User → Project → Local · last write wins on conflict
The critical design choice CLAUDE.md is delivered as user context — probabilistic compliance.
NOT as system prompt — which would be deterministic. Why? Because users edit CLAUDE.md freely, and a misworded line shouldn't be able to override the harness's deterministic safety guarantees. The deterministic enforcement happens in the permission rules, not in the prompt the model sees.

The 9 ordered context sources

Every model call assembles context from these nine sources, in this exact order:

1.  System prompt          // the immutable harness instructions
2.  Environment info       // cwd, OS, model, token budget
3.  CLAUDE.md hierarchy    // 4 levels merged: managed → user → project → local
4.  Path-scoped rules      // .claude/rules/*.md applied by file pattern
5.  Auto-memory            // LLM-selected memory files (max 5)
6.  Tool metadata          // schemas of available tools
7.  Conversation history   // past user/assistant turns
8.  Tool results           // stdout/stderr/files from prior calls
9.  Compact summaries      // chain-patched summaries from earlier compactions
Chapter 09 · Advanced

Subagents protect the parent's context budget.

Spawn an isolated worker. Get back only the summary.

The most expensive resource in an agent system isn't compute — it's tokens. Long subagent transcripts can blow up the parent's context faster than any other source. Claude Code's answer is sidechain isolation: each subagent writes its own JSONL file, runs its own conversation, and returns only a summary to the parent. The parent's context is structurally protected from subagent verbosity.

Fig. 9 · Animated
SkillTool vs AgentTool — the budget difference
Same task · two delegation strategies · radically different context cost
Cheap

SkillTool

Injects skill instructions into the current context. Same conversation window. Output, errors, intermediate junk — all of it lands in the parent's tokens. Use when the task is small and the output is short.

Expensive · ~7× tokens

AgentTool

Spawns a new isolated context window. The subagent does its own loop, its own tool calls, accumulates its own context. The parent only sees the final summary. Costs more total tokens, but keeps the parent context clean.

Chapter 10 · Advanced

Sessions are append-only logs.

Auditability over query power. Every event reconstructable without special tools.

Three persistence channels — session transcripts, global prompt history, subagent sidechains — all written as append-only JSONL files. No database, no schema migrations, no proprietary format. Compaction boundaries are recorded with headUuid, anchorUuid, and tailUuid; the session loader patches the message chain at read time. Nothing is destructively edited on disk.

Fig. 10 · JSONL structure
Chain-patched session timeline
Original messages stay on disk · compact summaries graft onto the chain at load time
The non-restoration invariant Permissions never persist across session boundaries.
Trust is always re-established in the current session. This accepts user friction as the cost of maintaining a strong safety invariant. A long-running, persistent permission grant would be a footgun — a single CLAUDE.md commit could quietly extend trust forever. The system instead pays the friction cost every resume.
Chapter 11 · Synthesis

Six decisions for your agent.

Not a coding tutorial. The design questions you must answer.

Pulling everything together, the paper offers a six-decision framework for anyone building an agentic system. Each decision is a fork in the road; Claude Code took specific paths, and you should know what they are before picking your own.

Decision 01

Reasoning placement

How much logic in the model vs. the harness? As models converge in capability, the harness becomes the differentiator.

Decision 02

Safety posture

How do you prevent harmful actions? Defense in depth fails when layers share failure modes. Audit them for shared dependencies.

Decision 03

Context management

What does the model see? Design for context scarcity from day one. Graduated > single-pass.

Decision 04

Extensibility

How do extensions plug in? Not all extensions need to consume context tokens. Layer the cost.

Decision 05

Subagent architecture

Shared or isolated context? Agent teams in plan mode cost ~7× tokens. Summary-only returns prevent context blow-up.

Decision 06

Session persistence

What carries over? Never restore permissions on resume. Auditability > query power.

The mega-takeaway

98.4%
The agent loop is easy to copy. Hooks, classifier, compaction, isolation — the cross-cutting harness — is not. The paper's central observation, after surveying every open-source reimplementation: people clone the loop in a weekend and never finish the harness. The loop is the brain; the harness is the body. Engineering effort flows where the code sits.

What the paper says is genuinely new

The paper distinguishes itself from the many community reverse-engineering efforts by offering a values → principles → implementation analytical framework. Where other repos map source code, this one maps the reasons for the source code — and uses the OpenClaw cross-system comparison to argue that cross-cutting integrative mechanisms, not modular features, are where the engineering complexity actually lives.
